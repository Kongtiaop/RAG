## 1. Strix — 开源 AI 渗透测试 Agent

**GitHub**：<https://github.com/usestrix/strix> ｜ 语言：Python ｜ 许可证：Apache-2.0

### 项目简介与定位

Strix 用自主 AI Agent 模拟真实黑客对应用做渗透测试：动态运行目标代码、发现漏洞、并用**可工作的 exploit 证明**漏洞真实存在，而不只是标记可疑模式。定位是"安全团队与开发者的自动化渗透同事"，支持 bug bounty 场景。

### 核心功能亮点

- 自主 Agent 编排：规划 → 探测 → 利用 → 报告全流程自动化，Agent 可自主决定下一步攻击路径
- **以 exploit 为证据**：每个发现附带可复现的利用链，消除"扫出来但不知道能不能打"的噪音
- 覆盖 Web 应用、API、代码库、CTF 等多种目标形态
- 支持安全自动化与 CI 集成，可嵌入 DevSecOps 流程

### 技术栈

Python 为主，LLM 多 Agent 架构（planner + worker 模式），可对接主流大模型。

### 关键指标（2026-10-24 实测）

- **Star 71,456 / Fork 7,964**，近 7 天增长约 +2.3k★，是当前安全分类中增长最快的仓库
- 贡献者 73 人；open issues 508（热度高的正常水位）
- 最近推送：**2026-10-24（当日）**；最新 Release v1.7.0（2026-10-05），迭代节奏约每月一版
- 项目 2025-08 创建，约 14 个月达到 71k★

### 适用场景

- 上线前对 Web 应用/API 做一轮自动化渗透验证
- Bug bounty 前期侦察与漏洞验证
- 安全团队扩充测试吞吐（人只审 AI 的报告与证据）

### 可靠性评估

**高**。增长与维护均为双第一梯队；Apache-2.0 宽松许可；当日仍有提交。注意：508 个 open issue 说明需求涌入快于消化，生产使用建议固定版本并先在测试环境跑。

### 上手建议

1. `pip install strix`（或按 README 使用安装脚本），配置 LLM API key
2. 先对一个**你有授权的**测试目标运行最小扫描，审阅报告中的 exploit 证据链
3. 只用于**自己拥有或获得书面授权**的目标——它打的是真 exploit，不是模拟

## 2. Shannon — 面向源码的 Web/API AI 渗透测试

**GitHub**：<https://github.com/KeygraphHQ/shannon> ｜ 语言：TypeScript ｜ 许可证：AGPL-3.0

### 项目简介与定位

Shannon 与 Strix 互补：它**先分析你的源代码**，从代码层面映射攻击向量，再对运行中的应用执行真实 exploit 来证明漏洞——口号是 "no exploit, no report"（没有利用证据就不出报告）。定位是嵌入研发流程的 AppSec 工具。

### 核心功能亮点

- 源码分析 + 动态验证双通道：静态找攻击面，动态跑 exploit 坐实
- 输出 SARIF 格式发现，可直接对接 GitHub Code Scanning 等 CI 门禁
- 明确面向 OWASP Top 10 与 API 安全场景
- CI/CD 友好，可在流水线中作为安全质量关卡

### 技术栈

TypeScript（Node.js），LLM 驱动的 Agent 架构。

### 关键指标（2026-10-24 实测）

- **Star 49,278 / Fork 5,638**，近 7 天 +307★
- 贡献者仅 7 人（增长主要由社区 star 驱动，核心开发集中）
- 最近推送：2026-10-15；最新 Release v3.4.0（2026-10-06），版本号已到 3.x，迭代快
- open issues 仅 29，维护响应干净
- 项目 2025-09 创建，13 个月到 49k★

### 适用场景

- 研发团队在 CI 中对自家服务做"代码级 + 运行时"双保险扫描
- AppSec 工程师批量审计多个内部服务
- 与 SAST/DAST 传统工具做交叉验证

### 可靠性评估

**中高，有两点需注意**。① **AGPL-3.0**：作为内部工具使用没问题，但若对其做修改并提供网络服务，需开源修改部分——商用集成前先过法务；② 贡献者仅 7 人，存在一定的单点维护风险（不过 29 个 open issue 的响应状态说明当前维护非常活跃）。

### 上手建议

1. 按 README 快速启动，配置模型 key，先扫描一个演示靶场（如 DVWA）熟悉报告格式
2. 接入 CI 时使用 SARIF 输出，把高危发现设为流水线失败条件
3. 注意误报治理：AI 渗透工具建议先观察两周误报率再设门禁阈值

## 3. Sniffnet — 舒适地监控你的网络流量

**GitHub**：<https://github.com/GyulyVGC/sniffnet> ｜ 语言：Rust ｜ 许可证：Apache-2.0

### 项目简介与定位

Sniffnet 是一个**桌面 GUI 网络流量监控工具**：实时展示本机所有连接的应用、域名、国家、协议与流量图表。定位是"让普通人也能看懂 Wireshark 级别的信息"——无需命令行技能即可做网络行为审计。

### 核心功能亮点

- 实时连接表：按应用/域名/IP/国家排序，直观看到"我的电脑在和谁说话"
- 服务与应用识别（含 6000+ 端口映射与协议探测）
- 流量图表与统计面板，支持导出 PCAP 深入分析
- 单一原生二进制，跨 Windows/macOS/Linux，性能由 Rust 保证

### 技术栈

Rust + iced GUI 框架；底层基于 pcap 抓包。

### 关键指标（2026-10-24 实测）

- **Star 41,682 / Fork 1,935**，近 7 天 +131★（稳定慢涨型）
- 贡献者 84 人；open issues 仅 59，issue 治理干净
- 最近推送：2026-10-21；最新 Release v1.5.1（2026-07-22，约 3 个月前——版本发布保守，但主干持续在动）
- 项目 2022 年创建，长期稳定维护，是 Rust 网络工具的标杆项目之一

### 适用场景

- 个人电脑排查"哪个软件在偷偷上传数据"
- 安全入门者学习网络协议与流量分析（比 tcpdump 友好得多）
- 作为渗透/取证工作的第一层快速侦察

### 可靠性评估

**高**。Apache-2.0；84 位贡献者；3 个月无新 Release 但主干 3 天前仍有推送，属于"低频发版、持续开发"的健康模式。GUI 工具功能面稳定，1.5.x 可放心日用。

### 上手建议

1. 从 GitHub Releases 下载对应平台安装包（Windows 需安装 Npcap）
2. 首次运行给抓包权限，观察 10 分钟正常基线，之后异常连接一眼可辨
3. 想深挖时点导出 PCAP，转 Wireshark 做协议级分析

## 4. NetBird — 基于 WireGuard 的零信任组网平台

**GitHub**：<https://github.com/netbirdio/netbird> ｜ 语言：Go ｜ 许可证：**BSD-3-Clause + AGPLv3 混合**（已核 LICENSE 原文）

### 项目简介与定位

NetBird 是开源零信任网络平台：用 WireGuard 建立免配置的 P2P 加密 overlay 网络，配合中心化的身份访问控制，让设备、服务、AI Agent 之间安全互联——无需开放端口、无需复杂防火墙规则、无需 VPN 网关。可视为 Tailscale 的开源自托管替代。

### 核心功能亮点

- 身份驱动的访问控制：接入即认证，按身份/组下发网络策略
- P2P 直连优先（打洞失败才走中继），延迟与吞吐接近局域网
- 自托管管理面：数据不出门，满足合规要求
- 官方描述中已把 **AI Agent 纳入组网对象**，面向 Agent 互联的新场景

### 技术栈

Go（客户端与管理面），WireGuard 数据面，配套 signal/relay 服务。

### 关键指标（2026-10-24 实测）

- **Star 30,175 / Fork 1,775**，近 7 天 +147★
- 贡献者 **172 人**，公司（NetBird GmbH）+ 社区双驱动，是 5 个项目里工程组织最成熟的一个
- 最近推送：**2026-10-24（当日）**；最新 Release v0.81.3（2026-10-19），迭代稳定
- open issues 796——绝对数高，但对 30k★ 的平台型项目属正常区间

### 适用场景

- 团队自托管 VPN 替代方案（办公网、开发环境、内网服务互通）
- 多云/混合云机器互联，替代手工 IPsec/防火墙配置
- 给内部 AI Agent/自动化设备分配零信任网络身份

### 可靠性评估

**高，但许可证要细看**（已核 LICENSE 原文）：仓库主体为 **BSD-3-Clause**（客户端可自由商用嵌入）；但 `management/`、`signal/`、`relay/`、`combined/` 四个**服务端目录为 AGPLv3**——若你修改服务端并对外提供网络服务，需开源修改。企业若介意，可购买其商业版或只自用不修改。172 位贡献者 + 当日提交 + 公司背书，维护可靠性是本日入选项目中最强的。

### 上手建议

1. 云端快速体验：注册其托管服务，装客户端，两台设备 5 分钟组网
2. 自托管：用官方 docker-compose 起 management + signal + relay，配置 IdP（支持 Keycloak/Authentik 等 OIDC）
3. 先给开发环境用起来（SSH/RDP 走 NetBird），再逐步收掉公网暴露面

## 5. Anubis — 用"工作量证明"拦截 AI 爬虫

**GitHub**：<https://github.com/TecharoHQ/anubis> ｜ 语言：Go ｜ 许可证：MIT

### 项目简介与定位

Anubis 自称"给进入的 HTTP 请求称重灵魂"：在反向代理层部署一个轻量门卫，对可疑客户端（主要是不声明身份的 AI 爬虫）发起基于浏览器的 **Proof-of-Work 挑战**——真人浏览器毫秒级通过，而海量爬虫要为每个页面付出算力代价。该项目诞生于开源维护者对抗"AI 公司爬虫压垮 GitLab/GNOME 服务器"的真实痛点。

### 核心功能亮点

- PoW 挑战机制：无需账号、无需验证码，真人几乎无感，爬虫成本指数级上升
- 基于 UA/请求特征的策略引擎，可白名单搜索引擎爬虫与已知合法 Bot
- 以反向代理中间件形式部署，Nginx/Caddy/Traefik/K8s Ingress 均可挂载
- 已被 GNOME、FediGit、Drupal 等多个大型基础设施站点采用，经过规模化验证

### 技术栈

Go 单二进制，前端极少量 JS（挑战脚本），无重型依赖。

### 关键指标（2026-10-24 实测）

- **Star 23,651 / Fork 792**，近 7 天 +198★，热度持续
- 贡献者 **194 人**——5 个项目中最多，社区参与度极高
- 最近推送：2026-10-23；最新 Release v1.28.2（**2026-10-23 当日发布**），发版极其勤快
- open issues 398，与活跃度匹配
- 项目 2025-03 创建，19 个月到 23.7k★，是"真实痛点驱动"项目的典型增长曲线

### 适用场景

- 开源项目托管站/文档站/博客被 AI 爬虫打爆流量的应急与长期防护
- 内容平台保护原创内容不被无差别抓取训练
- 与 WAF 互补：WAF 管攻击，Anubis 管"合法但过量"的流量

### 可靠性评估

**高**。MIT 许可；194 位贡献者；当日发布新版本；已被多个大型站点生产验证。唯一要权衡的是：PoW 挑战对老旧浏览器/无 JS 环境不友好，部署前需确认目标用户群体可接受。

### 上手建议

1. 用 Docker 单容器部署，在测试子域挂到 Nginx/Caddy 后面验证效果
2. 配置白名单：放行 Googlebot/Bingbot 等正经爬虫，避免 SEO 受损
3. 观察一周挑战通过率日志，再调高/调低难度阈值
