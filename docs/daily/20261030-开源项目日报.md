## 1. Agent-Reach — 给 AI 智能体装上"联网双眼"的信息获取能力层

**GitHub**：<https://github.com/Panniantong/Agent-Reach>

- **简介与定位**：一个给 AI Agent 用的统一信息获取层，让智能体真正"读得到、搜得到"互联网上的 Twitter/X、Reddit、YouTube、GitHub、B站、小红书、RSS 和普通网页——绕开 paywall、403 和登录墙。一个 CLI 覆盖多平台，零 API 费用。
- **核心功能亮点**：
  - 多平台统一读写接口：社交平台 + 长视频 + RSS + 网页一套 CLI 全搞定
  - 免费公共数据源聚合，无需逐平台申请 API Key
  - 面向 Agent 设计：输出即喂给 LLM 的结构化内容，可直接挂进 Claude Code 等 CLI 工作流
- **技术栈**：Python。
- **关键指标（2026-10-30 核实）**：⭐ 106,321 | 🍴 9,432 | 贡献者 38 | Open Issues 261 | 创建于 2026-02，8 个月约 13k★/月，是当下增速最陡的信息获取类项目；最新版 v1.6.0（2026-10-23 发布）。
- **适用场景**：给编码智能体/知识库机器人补"实时联网调研"能力；自媒体选题监控、多平台内容聚合；替代逐个平台写爬虫的重复劳动。
- **可靠性评估**：维护活跃（10-25 有推送、10-23 发版），MIT 许可证，社区规模大。注意 Open Issues 数量偏多（261），属高热度项目常态，重要功能建议先跑冒烟验证。
- **上手建议**：`pip` 安装 CLI 后先在命令行手动查一两个平台验证连通性，再接入你的 Agent 工作流；各平台接口可用性会随对方反爬策略波动，建议关键链路配置降级数据源。

## 2. Scrapling — 网站改版也不失效的"自适应"爬虫框架

**GitHub**：<https://github.com/D4Vinci/Scrapling>

- **简介与定位**：Python 自适应爬虫框架，覆盖"单次 HTTP 请求 → 全规模并发爬取"全谱系，内置反反爬绕过。最大卖点是**元素定位的适应性**：网站改版后，基于智能匹配算法，旧选择器大概率仍能找回目标元素。
- **核心功能亮点**：
  - 自适应元素定位：页面结构变化后自动重新匹配目标元素，显著降低爬虫"脆弱性"
  - 从轻量 HTTP 到 Playwright 级动态渲染全覆盖，按目标复杂度选武器
  - 内置隐身/指纹对抗能力（HTTP3、stealth 抓取）
- **技术栈**：Python（底层整合 requests/httpx 系与 Playwright 系生态）。
- **关键指标（2026-10-30 核实）**：⭐ 90,328 | 🍴 9,353 | 贡献者 41 | Open Issues 仅 22 | 最新版 v0.5（2026-10-17 发布），10-29 有推送；近 7 天约 +1.4k★。
- **适用场景**：长期运行的监控型采集（电商价格、舆情、招投标）；反爬中等强度站点的数据管道；不想每两周修一次选择器的工程化爬虫。
- **可靠性评估**：维护健康、Issue 积压极少（22 个），BSD-3-Clause 宽松许可证，文档完善。90k★ 中有社区对"自适应匹配"准确率的讨论，复杂站点仍建议人工复核采样。
- **上手建议**：从 `Fetcher`（纯 HTTP）起步，被封再升级到 `StealthyFetcher`/`PlayWrightFetcher`；把自适应定位用在"结构会变的列表页"上收益最大。遵守 robots.txt 与限速——礼貌的爬虫活得久。

## 3. moli — 用 Rust 重写的 AI 智能体专用无头浏览器

**GitHub**：<https://github.com/lexmount/moli>

- **简介与定位**：为 AI Agent 打造的生产级无头浏览器，主打"轻、快、高兼容"。智能体可通过 CLI、CDP、WebDriver Classic 或 WebDriver BiDi 四种通道驱动它抓页面、做搜索、跑浏览器自动化任务。2026 年 8 月创建，不到 3 个月冲到 21.5k★。
- **核心功能亮点**：
  - Rust 实现：内存占用低、启动快，单实例成本远低于 Chromium 系方案
  - 多协议兼容：CDP/WebDriver BiDi 双标准支持，现有 Playwright 式代码迁移成本低
  - 面向 Agent 的页面抽取：直接输出 LLM 友好的结构化内容
- **技术栈**：Rust。
- **关键指标（2026-10-30 核实）**：⭐ 21,558 | 🍴 580 | 贡献者 21 | 最新版 v1.1.19（2026-10-21 发布），10-30（今日）有推送；创建不足 3 个月约 8k★/月，本周日增最高 +484★，是当前浏览器自动化赛道增速第一的新项目。
- **适用场景**：大规模并发抓取/自动化集群的降本替代；给 Agent 运行时内嵌一个轻量浏览器；对 Chromium 授权与体积敏感的边缘部署。
- **可靠性评估**：维护极活跃（当日有提交、10 天内发版），Apache-2.0 许可证。风险点：项目年轻（版本 1.x 迭代快），Open Issues 459 偏多，兼容性长尾场景（重 JS 站点、复杂验证码）建议先小流量验证再上生产。
- **上手建议**：先用 CLI 模式 `moli fetch <url>` 体验抓取质量，再接 CDP 通道迁移现有自动化脚本；关注每两三天一发的 release 节奏，及时升级。

## 4. OfficeCLI — 让 AI 智能体直接读写 Word/Excel/PPT 的命令行 Office 套件

**GitHub**：<https://github.com/iOfficeAI/OfficeCLI>

- **简介与定位**：专为 AI 智能体设计的 Office 套件 CLI——读写、编辑、自动化 Word/Excel/PowerPoint，单二进制、免装 Office、开源免费。2026 年 3 月创建，是"Agent 操作办公文档"赛道目前星数最高的实现之一。
- **核心功能亮点**：
  - Excel：读工作表、筛选数据、生成透视表、绘制图表
  - Word：插入段落、套样式、生成报表、导出 PDF
  - PPT：新增幻灯片、插图、套模板、批量修改
  - 跨文档流水线：Excel 提数 → 生成 Word 报告 → 产出 PPT，一条命令链打通
- **技术栈**：C#（.NET），单二进制分发。
- **关键指标（2026-10-30 核实）**：⭐ 32,769 | 🍴 2,225 | 贡献者 20 | 最新版 v1.0.159（2026-10-27 发布），10-28 有推送；7 个月约 4.4k★/月，本周单日最高 +855★。
- **适用场景**：让 Claude Code/Cursor 等编码智能体直接产出 .xlsx/.docx/.pptx 交付物；周报、发票、财务报表等批量文档自动化；替代 VBA/Office Scripts 的低门槛方案。
- **可靠性评估**：发版极频繁（版本号已迭代 159+），Apache-2.0 许可证，维护活跃。注意：不同生态下格式还原度有差异，复杂版式（嵌套表格、特殊母版）产出前建议人工抽检。
- **上手建议**：下载单二进制后在 Claude Code 里配成工具/skill，用"读取一份现有 Excel → 生成汇总报告"做首个端到端验证，再逐步接入批量任务。

## 5. univer — 把 Office 做成 AI 智能体可编程运行时的全栈 SDK

**GitHub**：<https://github.com/dream-num/univer>

- **简介与定位**：自述为 "The Office Harness for AI Agents"——用一套 TypeScript SDK 覆盖表格、文档、幻灯片、关系型数据表与画板（PDF 在路上）。与"让 Agent 模拟人点鼠标"不同，univer 把 Office 本身做成 agent 可结构化读写的运行时。
- **核心功能亮点**：
  - 全 Canvas 渲染 + 自带公式引擎：不是"壳"，公式、数字格式、筛选、条件格式、数据验证皆为原生能力
  - 同构设计：同一套代码跑浏览器 UI 或 Node.js 无头模式（后者就是给 agent 与自动化准备的）
  - Agent 协作面：Facade API 结构化读写 + 渲染截图/布局诊断自检；"worktree 式"草稿隔离—人审—合并的工作流
  - 生态配套：univer-mcp、AI SDK、agent skills，社区已有多种 AI 客户端插件
- **技术栈**：TypeScript。
- **关键指标（2026-10-30 核实）**：⭐ 22,800 | 🍴 1,913 | 贡献者 73（本期最高）| 最新版 v1.3.0（2026-10-29 发布），10-29 有推送；本周单日 +14~19★ 稳定增长。
- **适用场景**：自建 Web 端表格/文档产品（替代 Luckysheet 的正式答案）；给智能体提供"真正可编程的 Excel 引擎"做数据分析后端；在线协同办公场景。
- **可靠性评估**：团队化维护（73 贡献者、DreamNum 团队），Apache-2.0 许可证，v1.x 版本线已稳定，是 5 个项目中工程成熟度最高的。重前端集成，纯 CLI 场景用 OfficeCLI 更省事。
- **上手建议**：先跑官方 playground 体验 Facade API，服务端场景直接用 Node.js 无头模式；做 agent 集成优先看 univer-mcp 与 AI SDK 文档。

## 本期趋势观察

1. **"可被智能体操作"已成默认准入特性**：5 个项目中有 4 个（Agent-Reach、moli、OfficeCLI、univer）明确以 AI Agent 为第一用户，传统"给人用的工具"正在被"给 Agent 用的能力层"重新定义。
2. **爬虫赛道分三层收敛**：能力层（Agent-Reach 统一聚合）、框架层（Scrapling 自适应抗改版）、运行时层（moli Rust 无头浏览器），各自解决"被封、失效、贵"三个痛点。
3. **Office 自动化两条路线**：CLI 外挂式（OfficeCLI，面向已有 Agent 工作流）与运行时内置式（univer，面向自建产品），选型取决于你是"给现有 Agent 加能力"还是"造一个新 Office 产品"。
