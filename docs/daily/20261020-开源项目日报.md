## 1. archify — 把"一段话"变成可交互架构图

**项目简介与定位**
[archify](https://github.com/tt-a1i/archify) 是一个面向 AI 编码代理（Claude Code、Codex 等）的 Agent Skill：输入系统描述、方案文档或直接指向代码库，即可生成精致的可交互图表（架构图、工作流、调用时序、数据流、生命周期）。生成结果是**独立 HTML 文件**——同事用浏览器打开就能点选节点、查看细节、追踪路径，无需任何服务端。官网：https://archify.si

**核心功能亮点**
- 支持架构、工作流、时序、数据流、生命周期等多类图表
- 图表可对话式追问："高亮 cache-miss 路径""加上鉴权环节"
- 输出独立 HTML，可导出图片与分享卡片，直接用于文档和汇报
- 适合新人 onboarding 与架构变更评审场景

**技术栈**：JavaScript；产物为自包含 HTML + SVG

**关键指标**（2026-10-20 实测）
- ⭐ 85,906 | 🍴 5,848 | 贡献者 87 人 | Open Issues 259
- 创建于 2026-04-15，最近推送 2026-10-19，最新版本 v3.2.0（2026-10-19 发布）
- 增长势头：2026 年 9 月单月约 +33.4k star，是当月 GitHub 全榜增速第一梯队

**适用场景**：向非技术干系人讲解系统架构；写设计文档/汇报材料时的图表生成；代码库快速摸底。

**可靠性评估**
- 维护活跃度：**极高**。创建仅 6 个月，近 7 日持续有提交，昨日刚发 v3.2.0
- 社区健康度：贡献者 87 人、watcher 237 人，issue 数量与热度匹配
- 许可证：**MIT**，无商用风险
- 风险提示：项目尚年轻，API 形态可能随大版本（已到 v3.x）调整；生成图表的关系准确性依赖输入描述的质量，需人工校对

**上手建议**
1. 在支持 Agent Skill 的环境（Claude Code / Codex 等）中安装 skill
2. 从一个熟悉的模块开始试用，先让它读代码库生成架构图，与实际对照验证准确性
3. 把生成的 HTML 纳入团队文档库，配合导出图片用于周报/评审

## 2. impeccable — 让 AI 生成的界面真正"能看"

**项目简介与定位**
[impeccable](https://github.com/pbakaus/impeccable)（作者 Paul Bakaus，前 Google Chrome DevTools 团队成员）是一套面向 AI 编码代理的**设计语言**：一个 skill、24 条命令、实时浏览器迭代，外加 59 条确定性检测规则，用于系统性修正 AI 生成前端"能用但难看"的通病。官网：https://impeccable.style

**核心功能亮点**
- 确定性检测规则（59 条）而非纯 prompt 说教，可机器校验设计问题
- 内置实时浏览器迭代能力，改完即见效果
- 与主流 AI 编码工具（Claude Code 等）集成，按命令逐项打磨界面

**技术栈**：核心以 Rust 实现（CLI 性能好）；面向 JavaScript/前端工作流

**关键指标**（2026-10-20 实测）
- ⭐ 83,287 | 🍴 5,038 | 贡献者 53 人 | Open Issues 52
- 创建于 2025-11-16，最近推送 2026-10-19，最新版本 cli-v4.7.0（2026-10-19）
- 增长势头：10 月初约 74.3k → 10 月 20 日 83.3k，两周半 +9k，持续高速增长

**适用场景**：用 AI 生成落地页/管理界面后的设计质检；团队建立 AI 前端产出的统一设计基线；vibe coding 工作流的收尾打磨。

**可靠性评估**
- 维护活跃度：**极高**。发布节奏密集（CLI 已迭代到 v4.7.0），issue 积压少（52 个）
- 社区健康度：单人主导色彩较浓（pbakaus 个人项目），53 位贡献者但核心决策集中；好在项目规则明确、代码工程化程度高
- 许可证：**Apache-2.0**，宽松且含显式专利授权
- 风险提示：作者个人品牌项目，若作者投入减弱需观察；不过当前节奏未见衰减

**上手建议**
1. 通过 CLI 安装并挂接到现有 AI 编码工作流
2. 对最近一个 AI 生成的页面跑一遍检测规则，直观感受问题检出能力
3. 把它定位为"最后一道设计门禁"而不是替代设计判断

## 3. diagram-design — 编辑级图表设计的 Agent Skill

**项目简介与定位**
[diagram-design](https://github.com/cathrynlavery/diagram-design) 聚焦一件事：让 AI 编码代理（Claude Code、Codex、Copilot、Cursor 等）生成**编辑级（editorial）质量的图表**。支持 44 种图表类型（架构图、流程图、甘特图、UML 类图、数据库 schema 等），产物为自包含 HTML + SVG。官网：https://diagramdesign.dev

**核心功能亮点**
- 44 种图表类型覆盖面广，远超同类 skill
- 明确的设计主张：无阴影、无"Mermaid 味"的通用圆角框，追求出版物级排版
- 产物零依赖，可直接嵌入文档、博客、汇报

**技术栈**：HTML + SVG（纯静态产物，无运行时依赖）

**关键指标**（2026-10-20 实测）
- ⭐ 58,505 | 🍴 3,757 | 贡献者 57 人 | Open Issues 仅 42
- 创建于 2026-04-16，最近推送 2026-10-20（**当日仍在更新**）
- 增长势头：与 archify 同属 2026 年"Agent Skill 图表赛道"双雄

**适用场景**：技术文档配图、架构评审材料、博客/教程插图——任何需要"图表好看"的场合。

**可靠性评估**
- 维护活跃度：**极高**，推送更新就在今天
- 社区健康度：issue 积压极低（42 个），响应速度快
- 许可证：**MIT**，无商用风险
- 风险提示：无正式 release（以文件/skill 形式分发），更新跟随仓库 HEAD，升级时留意破坏性变更

**上手建议**
1. 将 skill 装入你的 AI 编码工具目录
2. 用同一份系统描述分别对比它与 archify 的产出，选定与团队审美匹配的一个
3. 将图表生成纳入文档模板，统一团队配图风格

## 4. gods-eye-view — 浏览器里的实时开源情报 3D 地球

**项目简介与定位**
[gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)（"上帝视角"）把航班（ADS-B）、船舶（AIS）、卫星（CelesTrak TLE）、地震（USGS）等**公开广播信号**实时叠加在照片级 3D 地球上，配语音 Agent 免提操控。纯前端构建（CesiumJS + Vite），**无后端服务器、无付费数据源**。作者 Bilawal Sidhu 是 YouTube 地理空间可视化创作者，该项目 8 月底曾登顶 GitHub Trending 全榜。官网：https://maptheworld.ai/

**核心功能亮点**
- 多源公开情报信号统一到一个"一眼看懂"的界面
- 纯浏览器运行，本地部署零成本
- 3D 地球交互体验出色，可追踪航班、船舶、卫星轨迹

**技术栈**：JavaScript、CesiumJS、Vite（WebGL）

**关键指标**（2026-10-20 实测）
- ⭐ 58,296 | 🍴 11,365 | 贡献者 78 人 | watcher 1,059（五者中最高）
- 创建于 2026-06-22，最近推送 2026-10-20，最新版本 v0.2.1（2026-10-03）
- 增长势头：8 月底约 12.3k → 10 月中旬 55.5k → 今日 58.3k，约 7 周 +46k，为今日五者中最陡曲线

**适用场景**：地理空间数据可视化学习范例；OSINT/态势感知的轻量入门；个人兴趣探索与内容创作素材。

**可靠性评估**
- 维护活跃度：**高**，近乎每日有提交，版本推进到 v0.2.x
- 社区健康度：fork 数 11.4k、watcher 1,059，社区参与度五者中最高；但 open issues 405 个， issue 处理压力较大
- 许可证：**⚠️ 风险点**。仓库许可证为 "Other / NOASSERTION"（自定义条款），商用集成前务必阅读 LICENSE 原文；项目源自创作者内容生态，条款可能限制商用
- 风险提示：v0.x 阶段 API 与数据层不稳定；依赖多个外部公开数据源的可用性

**上手建议**
1. 克隆后本地起静态服务即可体验，先玩数据图层再读代码
2. 学习价值重点在 CesiumJS 的多源数据流整合与大规模点渲染
3. 若考虑商用/二次分发，**先确认自定义许可证条款**，必要时联系作者

## 5. openui — 生成式 UI 的开放标准

**项目简介与定位**
[openui](https://github.com/thesysdev/openui)（Thesys 出品）试图为"生成式 UI"定义一个**开放标准**：一套紧凑的流式优先描述语言（OpenUI Lang），让 LLM 输出结构化、可直接渲染的 UI——而不是纯文本或 JSON 小票。配套提供 React、Vue、Svelte、Angular 运行时。官网：https://www.openui.com

**核心功能亮点**
- 流式优先：LLM 边生成边渲染，交互体验接近打字机出 UI
- 多框架运行时（React/Vue/Svelte/Angular），不锁死技术栈
- 标准化思路：以开放协议而非单一组件库切入，生态位类似"生成式 UI 的 HTML"

**技术栈**：TypeScript；多框架 SDK

**关键指标**（2026-10-20 实测）
- ⭐ 12,234 | 🍴 828 | 贡献者 53 人 | Open Issues 169
- 创建于 2024-12-02，最近推送 2026-10-19，最新版本 @openuidev/cli@0.6.0（2026-10-15）
- 增长势头：属"稳健上升型"而非爆发型，但方向卡位（GenUI 标准）在 2026 年 AI 应用浪潮中持续受益

**适用场景**：AI 对话产品中用可交互组件替代纯文本回复；Agent 工作流的可视化编排界面；需要 LLM 实时"画出"界面的产品。

**可靠性评估**
- 维护活跃度：**高**。公司（Thesys）持续投入，发布节奏规律
- 社区健康度：背靠公司团队，53 位贡献者、issue 响应正常；watcher 较少（36），社区自发生态尚在早期
- 许可证：**MIT**，无商用风险
- 风险提示：标准尚未形成事实垄断，需跟踪行业收敛情况（Shadcn generative-ui、蚂蚁 Ant Design X 等同场竞技）；0.x 版本语义化变更频繁

**上手建议**
1. 先跑官方 React 示例，体验流式生成 UI 的效果差异
2. 在客服/问答类 AI 产品中试点：把"文字列表"回复替换为 OpenUI 渲染的交互组件
3. 评估时关注规范稳定性与多框架运行时的成熟度差异
