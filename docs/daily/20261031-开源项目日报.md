## 1. REA — Reverse Engineer Anything：AI 逆向工程平台

**GitHub**：<https://github.com/morluto/rea> ｜ 语言：TypeScript ｜ 许可证：MIT

### 项目简介与定位

REA（Reverse Engineer Anything）让 AI 编码 Agent 对应用、二进制、网站做逆向工程：通过一个 MCP Server + 同功能 CLI，把分析结果（附证据）返回给 Claude Code、Codex、Cursor、Gemini CLI 等主流 Agent，Agent 据此解释一个功能的行为、甚至编写并测试重新实现。口号是"Reverse engineer anything with agents, from app behavior down to native binaries"。它是把 Ghidra/IDA 这一专业逆向工作流首次大规模 Agent 化的项目。

### 核心功能亮点

- **单一 MCP 接口覆盖全谱系标的**：原生二进制、JavaScript/Electron 应用、.NET 程序集、网站、Android APK、固件、pcap 抓包文件
- **证据优先**：每条发现附带支撑证据，而非只给结论；分析在**本机执行**，数据不出门
- `npx rea-agents setup` 一条命令向主流 Agent 注册，零配置接入
- 静态 JS 分析开箱即用；原生二进制分析可对接 Hopper / Ghidra / IDA，复用现有逆向工具链

### 技术栈

TypeScript（Node.js ≥ 22.19），MCP Server + CLI 双形态；原生分析经桥接 Ghidra/IDA/Hopper 完成。

### 关键指标（2026-10-31 实测）

- **Star 412,494 / Fork 103,181**，单日仍 +2k★ 左右——2026-04-14 创建，**约 6 个半月达到 41 万星**，是本期所有日报收录项目中的历史最高增速
- 贡献者 **352 人**；open issues 1,387（增长速度远超消化速度的正常水位）
- 最近推送：**2026-10-30**；最新 Release rea-agents-6.8.0（2026-10-25），周更节奏，API 仍在快速演进
- 本期热度带动 NSA/ghidra 一并重回 GitHub Trending，社区外溢效应明显

### 适用场景

- 接手无文档遗留系统：让 Agent 用 REA 摸清第三方二进制/组件的真实行为
- 安全研究：漏洞复现、恶意样本行为分析的第一层自动化
- 团队逆向知识沉淀：分析结论以"证据 + 结论"结构化留存，可被 Agent 反复引用

### 可靠性评估

**高活跃、但 API 未冻结**。MIT 许可；352 位贡献者 + 隔日提交 + 周更发版，维护状态无可挑剔。两点注意：① 6.5 个月 41 万星的增长曲线历史罕见，说明需求真实但也意味着文档/教程滞后于功能；② open issues 近 1,400，遇到问题时优先查最新 issue 再报新。版本号已至 6.8.0 但仍属快变期，生产使用建议锁死版本。

### 上手建议

1. `npx rea-agents setup` 注册到你的 Agent（Node.js ≥ 22.19），先从静态 JS 分析入手（无需额外逆向软件）
2. 原生二进制分析前，本机装好 Ghidra（免费）即可起步，IDA/Hopper 可选
3. 让 Agent 分析时在提示里要求"给出证据链"，并人工抽查证据真实性——逆向结论务必二次验证

## 2. NemoClaw — NVIDIA 出品的 Agent 安全运行栈

**GitHub**：<https://github.com/NVIDIA/NemoClaw> ｜ 语言：TypeScript ｜ 许可证：Apache-2.0

### 项目简介与定位

NemoClaw 是 NVIDIA 开源的参考级技术栈，用于**在 NVIDIA OpenShell 沙箱内更安全地运行 AI Agent**（如 OpenClaw、Hermes、LangChain Deep Agents），配套托管推理、网络策略与生命周期管理 CLI。它回答的问题是：当你把有文件系统/网络权限的 Agent 放进生产环境，如何让"失控的 Agent"炸不掉基础设施。与攻防工具不同，它属于**防守侧的运行时隔离层**。

### 核心功能亮点

- **沙箱优先的 Agent 执行模型**：Agent 行为被限定在 OpenShell 沙箱边界内，与宿主基础设施解耦
- 托管推理接入：模型调用统一收口，敏感数据不出安全边界
- 内置网络策略引擎：Agent 能访问哪些端点、哪些协议，按策略显式声明
- CLI 管理全生命周期：创建沙箱、注入凭证、销毁现场，一条命令完成，凭证不落明文

### 技术栈

TypeScript，NVIDIA OpenShell 沙箱底座；面向 OpenClaw / Hermes / LangChain Deep Agents 等主流 Agent 框架。

### 关键指标（2026-10-31 实测）

- **Star 22,895 / Fork 3,182**，2026-03-15 创建，7 个半月达到 22.9k★（约 3k★/月）
- 贡献者 **184 人**——大厂项目里少见的高社区参与度，非单团队封闭开发
- 最近推送：**2026-10-31（当日）**；**尚无正式 Release**——main 主线即使用线
- open issues 808，绝对数偏高，与高速迭代期的流量涌入匹配

### 适用场景

- 企业内网部署会动文件、发请求的 AI Agent 前的安全底座
- 多租户 Agent 平台：为不同租户的 Agent 提供相互隔离的执行环境
- Agent 行为审计与复现：沙箱现场可完整保存与回放

### 可靠性评估

**中高，有三个明确的点**。① NVIDIA 背书 + Apache-2.0 + 184 贡献者 + 当日提交，工程资源无忧；② **无正式发版**，API/CLI 处于 v0 形态，随时可能破坏性变更——只建议测试环境先行；③ 808 个 open issue 的响应压力开始显现，关键问题建议同时关注 NVIDIA 官方渠道。

### 上手建议

1. 按 README 部署 OpenShell + NemoClaw CLI，先跑官方示例 Agent 感受沙箱边界
2. 给你的 Agent 写最小网络策略（默认拒绝，显式放行必需端点），观察拦截日志
3. 在沙箱内故意跑一次"越界行为"测试（如访问未授权端口），验证隔离真实生效再上生产

## 3. Web-Check — 一站式网站情报 OSINT 仪表盘

**GitHub**：<https://github.com/lissy93/web-check> ｜ 语言：TypeScript ｜ 许可证：MIT

### 项目简介与定位

Web-Check 是开源 OSINT 工具：输入任一网址，一页汇总 IP 信息、SSL 证书链、DNS 记录、Cookie、HTTP 响应头、服务器位置、开放端口、技术栈识别等数十项情报。定位是"安全评估与资产摸底的第一站"——原本要开五六个在线工具拼凑的信息，一个仪表盘全给。官方实例公开可用，也可一键自托管。

### 核心功能亮点

- 单页聚合 30+ 类情报：DNS/SSL/WHOIS/端口/技术栈/归档历史/跨域资源等
- 自托管友好：Docker/Vercel/Netlify 部署一条命令，内网目标也能测
- 结果可视化分层展示，从"一眼判断"到"逐项深挖"都覆盖
- API 化输出，可被脚本与 Agent 调用做自动化侦察第一环

### 技术栈

TypeScript（Node.js + React 前端），后端聚合多个公开情报数据源，无重型自建依赖。

### 关键指标（2026-10-31 实测）

- **Star 35,309 / Fork 2,919**，稳定增长型（网络分类中 Star 第三高的工具类项目）
- 贡献者 40 人；**open issues 仅 1**——issue 治理是本期 5 个项目中最干净的
- 最近推送：2026-10-30；最新 Release 2.3.0（2026-10-02），迭代稳定
- 项目 2023-06 创建，3 年多长期活跃维护，无断更记录

### 适用场景

- 渗透测试/众测前的目标摸底与资产测绘
- 运维自查：核对本域名的证书、DNS、响应头配置是否合规（如 CSP、HSTS）
- 教学演示：讲解 DNS/SSL/HTTP 头等概念时最直观的实时教具

### 可靠性评估

**高**。MIT 许可；40 贡献者 + 3 年持续维护 + 仅 1 个 open issue，是典型的"成熟低噪"项目。注意：它只做**被动信息收集**，不含漏洞利用能力；对目标发起的探测仍需确保获得授权。

### 上手建议

1. 直接用官方实例输入你的域名做一次体检，重点看安全响应头与 SSL 链两项
2. 自托管到内网用于内部资产巡检：`docker` 单容器即可
3. 用其 API 把"域名体检"挂进 CI/CD，发布前后各跑一次做配置漂移检测

## 4. ecapture — 无证书的 TLS 明文捕获（eBPF）

**GitHub**：<https://github.com/gojue/ecapture> ｜ 语言：C ｜ 许可证：Apache-2.0

### 项目简介与定位

ecapture 基于 eBPF 的 uprobe 机制，在 Linux/Android 上**不装 CA 证书、不做中间人代理**直接捕获本机进程的 SSL/TLS 明文。原理是 hook OpenSSL/BoringSSL/GnuTLS 等加密库的写函数与 SSL_write/SSL_read 调用，输出兼容 Wireshark 的 pcapng 格式（可还原解密后的流量时序）。传统抓包排查 HTTPS 流量要配 MITM 证书链，ecapture 让这一步彻底消失——网络取证与安全审计场景的刚需工具。

### 核心功能亮点

- **零配置解密**：无需向目标系统注入证书，对生产环境的侵入性几乎为零
- 多加密库覆盖：OpenSSL、BoringSSL、GnuTLS、GoCrypto（Go 1.14+ TLS）、LibreSSL
- 输出 pcapng 可直接导入 Wireshark 做协议级分析；也支持纯文本明文模式
- Android 支持：可抓 App 的 HTTPS 明文，移动端流量分析利器
- bash/mysql/postgres 等特定协议的明文 hook 模块

### 技术栈

C（eBPF/uprobe，基于 cilium/ebpf 生态），单二进制部署，内核要求支持 eBPF（≥ 4.4 部分功能 / 5.2+ 全功能）。

### 关键指标（2026-10-31 实测）

- **Star 15,522 / Fork 1,648**，2022-03 创建，4 年长期稳步增长
- 贡献者 60 人；**open issues 仅 4**——15k 星级项目里极罕见的高治理水位
- 最近推送：**2026-10-31（当日）**；最新 Release v2.9.0（2026-10-24），一周前刚发版
- 中文作者主导（国内 eBPF 生态代表项目），中英文文档均完善

### 适用场景

- 生产环境 TLS 流量故障排查：不重启服务、不装证书，直接看清密文里的真实内容
- 恶意软件行为分析：确认可疑进程向外发送了什么
- Android App 安全测试：替代 Xposed/Frida 证书钉扎绕过方案，抗检测性更好

### 可靠性评估

**高**。Apache-2.0；60 贡献者；当日提交 + 当周发版；4 个 open issue 的响应纪律说明维护者极其勤勉。两点边界提醒：① 需要 root/CAP_BPF 权限运行，权限要求与攻击面并存，务必只在自己拥有/授权的系统上使用；② 内核版本过旧（<5.2）时部分 hook 不可用，老旧生产机先跑兼容性自检。

### 上手建议

1. Linux 5.2+ 内核机器上下载 release 二进制，`sudo ./ecapture tls -w out.pcapng` 抓本机 HTTPS 明文
2. pcapng 拖进 Wireshark 对照看，先在测试机验证，再规划生产排查窗口
3. Android 场景需 root + 内核支持 eBPF 的机型；从 README 的兼容性矩阵开始查你的设备

## 5. AI-Infra-Guard — 腾讯朱雀实验室的全栈 AI 红队平台

**GitHub**：<https://github.com/Tencent/AI-Infra-Guard> ｜ 语言：Python ｜ 许可证：Apache-2.0

### 项目简介与定位

AI-Infra-Guard（A.I.G）是腾讯朱雀实验室开源的 AI 红队平台，扫描对象不是传统网站，而是**AI 生态本身**：AI Agent、MCP Server、Agent Skill 文件、AI 基础设施组件（推理框架、模型服务）的已知漏洞与配置风险，外加针对 LLM 的越狱攻击评测。当企业开始把 Agent 和 MCP 接进内网，这类"给 AI 基础设施做漏扫"的工具是全新的刚需品类。

### 核心功能亮点

- **五类扫描一体**：Agent Scan / Skills Scan / MCP Scan / AI Infra Scan / LLM 越狱评测
- 内置 AI 组件指纹库：识别 Ollama、vLLM、ComfyUI 等常见 AI 服务及其已知 CVE/未授权访问
- 越狱评测：内置提示词攻击集，对自建模型/Agent 的安全水位做量化评分
- MCP Scan 检测 MCP Server 的工具投毒、命令注入、配置泄露等新型攻击面

### 技术栈

Python，扫描引擎 + 指纹规则库架构，规则与 PoC 库持续更新；CLI 与 Web 界面双形态。

### 关键指标（2026-10-31 实测）

- **Star 7,235 / Fork 703**，2024-12 创建，2026 年下半年进入快速增长期
- 贡献者 **68 人**，腾讯朱雀实验室团队 + 社区共同维护
- 最近推送：2026-10-30；最新 Release **v4.6.8（2026-10-29）**——发版节奏极快，4.x 大版本年内高频迭代
- open issues 24，维护响应干净

### 适用场景

- 企业上线自有 AI Agent / MCP 服务前的入场安全检查
- 定期巡检内网 AI 基础设施（推理服务、模型仓库）的暴露面与已知漏洞
- 模型发布前的越狱鲁棒性评测，产出可量化的安全评分

### 可靠性评估

**高**。Apache-2.0；大厂安全实验室背书 + 68 贡献者 + 隔日发版，是"AI 基础设施漏扫"这个新品类里目前最成熟的选项。注意：指纹库与 PoC 的时效性是这个品类的生命线，务必跟随主线更新；扫描自带攻击性，只对**授权资产**使用。

### 上手建议

1. `pip` 安装后先对**你自己的**推理服务（如内网 Ollama）跑一次 AI Infra Scan，看未授权访问与默认配置风险
2. 把 MCP Scan 纳入你的 MCP Server 上线 checklist，重点看工具描述注入项
3. 越狱评测模块对内部 Agent 跑一轮基线，之后每次 Agent 提示词大改后回归一次
