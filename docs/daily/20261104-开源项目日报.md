## 1. oceanbase/seekdb — AI 原生搜索数据库（Agent 状态存储）

**项目简介与定位**：OceanBase 官方推出的 AI 原生搜索数据库，口号是 "Write. Search. Fork. The State Store for AI Agents"。把向量、全文、结构化与半结构化数据统一在一个引擎里，专为 AI Agent 的存储与检索场景设计——Agent 越来越需要"一个地方放状态、随处可查、还能像 Git 一样 fork 出分支试错"。

**核心功能亮点**：
- 单引擎统一向量检索、全文检索、结构化 SQL 与半结构化数据，无需在多个存储间拼装
- COW（Copy-on-Write）沙箱分支：Agent 可以 fork 出数据库分支做实验，验证后再合并，"Write. Search. Fork" 即由此而来
- MySQL 兼容接入，生态工具链可直接复用
- 提供 pyseekdb Python 客户端，Agent 框架集成成本低

**技术栈**：C++（内核），Python 客户端，Apache-2.0。

**关键指标**（GitHub API，2026-11-04 实测）：
- Star **3,227** · Fork 1,242 · 贡献者 **46** · open issue 711
- 创建于 2025-10-21，约一年 3.2k★；**当日（11-04）仍有推送**，维护极活跃
- 最新 release：v1.4.0（2026-08-27）
- 仓库：https://github.com/oceanbase/seekdb

**适用场景**：为 Agent/LLM 应用选统一状态存储（记忆、会话、知识库、业务数据一库搞定）；需要"COW 分支试错"类 Agent 工作流的团队；已有 MySQL 生态想平滑叠加向量/全文能力的后端。

**可靠性评估**：OceanBase 官方背书 + 46 名贡献者 + 当日仍有提交，属于大厂项目中的健康样本。两点注意：① open issue 711 偏高（热度带来的问题积压），提 issue 前先搜索是否已有同类；② 正式 release 节奏约 2~3 个月一版，介于稳定版与快速迭代之间。

**上手建议**：`pip install pyseekdb` 走 Python 路线最快；先在一个 Agent 记忆存储场景做 PoC，重点验证 COW 分支语义是否匹配你的 Agent 检查点需求；生产引入建议等 v1.5 稳定后再评估。
