## 1. beenuar/AiSOC — 开源自托管 AI 安全运营中心（SOC）

> 🔗 https://github.com/beenuar/AiSOC

- **简介与定位**：开源、可自托管的 AI 安全运营中心。摄取安全遥测数据（告警/日志），自动做告警融合去重，再由 LLM Agent 逐条分诊（triage）、按 MITRE ATT&CK 框架展开调查，最终产出**人类必须审批**的处置建议。核心卖点是每个 Agent 决策都有**可回放、可审计的决策台账**（decision ledger）——这直接回应了"AI 参与安全运营不可信"的最大顾虑。
- **核心功能亮点**：
  - 告警融合：跨源告警归并去重，减少告警疲劳；
  - LLM Agent 分诊：自动判级、给出理由与证据链；
  - MITRE ATT&CK 映射的调查流程；
  - 决策台账可回放，人工审批兜底（自动化仅到"建议"为止）。
- **技术栈**：Python 为主，LLM Agent 编排 + 自托管部署。
- **关键指标**（2026-11-07 核实）：⭐ 6,681 · 🍴 716 · 贡献者 29 · open issue 仅 **7** · 最近推送 2026-11-07（当日）· 最新版 v22.2.0（2026-11-06 发版，发版节奏极快）· 近 7 天提交 100+。2026-05 创建，约 1.1k★/月，第三方榜单显示其日增曾达 +267★。
- **适用场景**：中小团队买不起 Splunk/Palo Alto Cortex XSOAR 的场景，自建"穷人版 SOC"；已有 SIEM/Wazuh/ELK 的团队叠加一层 AI 分诊；红蓝对抗演练的告警自动化初筛。
- **可靠性评估**：**优秀**。MIT 宽松协议；open issue 只有 7 个（6.7k★ 体量下极罕见），说明维护者响应极快；当日有推送、隔日有发版，迭代活跃；29 个贡献者、单仓库健康增长，无过气迹象。风险点：SOC 类工具对误报率敏感，LLM 分诊质量依赖模型选型，建议灰度接入。
- **上手建议**：Docker 自托管，先接 1~2 个低危告警源跑通"融合→分诊→台账"闭环，再逐步扩大接入面；把人工审批环节当作审计要求而非累赘保留。

## 2. NVIDIA/SkillSpector — AI Agent Skill 安全扫描器

> 🔗 https://github.com/NVIDIA/SkillSpector

- **简介与定位**：NVIDIA 出品的 **AI Agent Skill 静态安全扫描器**：在安装 Claude Code / Codex / MCP 的 Skill 之前，检测其中的漏洞、恶意模式、提示注入、数据外传与供应链风险。这是去年"Agent Skill 生态爆发"的直接产物——Skill 本质是可执行指令包，却长期没有像 npm audit / pip-audit 那样的安装前审查工具，SkillSpector 补的就是这个空位。
- **核心功能亮点**：
  - 检测面覆盖：恶意模式、提示注入、数据外传（exfiltration）、供应链风险；
  - 面向 Claude Code、Codex、MCP 三大 Skill 生态；
  - 安装前（pre-install）扫描，与上一期 NemoClaw（运行时隔离）构成"安装前审查 + 运行时隔离"的双层防线；
  - NVIDIA 官方维护，规则库持续更新。
- **技术栈**：Python。
- **关键指标**（2026-11-07 核实）：⭐ 24,750 · 🍴 2,147 · 贡献者 **120** · open issue 171（体量下属正常偏高）· 最近推送 2026-11-06 · 最新版 v2.13.4（2026-11-04，小步快跑发版）· 近 7 天提交 100+。2026-03 创建，约 3.3k★/月，增速在安全类项目中属第一梯队。
- **适用场景**：企业统一管理 Agent Skill 仓库时的准入门禁（CI 中扫描）；个人开发者安装第三方 Skill/MCP 前的例行检查；安全团队审计内部 Agent 能力面。
- **可靠性评估**：**优秀**。Apache-2.0 宽松协议；大厂背书 + 120 贡献者 + 当周发版，维护无虞；同类工具尚无同体量竞品。风险点：open issue 171 偏高（社区涌入快于消化）；静态扫描天然存在绕过空间，应作为纵深防御的一层而非唯一防线。
- **上手建议**：先对团队 Skill 仓库全量跑一遍基线扫描，再把 CLI 接进 CI/CD 作为 Skill 上架门禁；规则误报可提 issue，NVIDIA 响应较快。

## 3. vxcontrol/pentagi — 全自主 AI 渗透测试 Agent 系统

> 🔗 https://github.com/vxcontrol/pentagi

- **简介与定位**：Go 实现的**全自主多 Agent 渗透测试系统**：AI Agent 自主规划并执行渗透步骤，运行在隔离 Docker 沙箱内，内置 nmap、metasploit、sqlmap 等 20+ 传统安全工具——本质是给经典渗透工具箱装了一个"会自己决策的大脑"。定位与此前收录的 strix（74k★）、shannon（51k★）同属 AI 渗透赛道，差异化在于：pentagi 更老牌（2025 年初创建）、Go 技术栈、沙箱隔离做得更彻底。
- **核心功能亮点**：
  - 多 Agent 协作：规划、执行、验证分层；
  - 隔离 Docker 沙箱执行，攻击动作不出容器；
  - 复用 20+ 成熟安全工具，而非重新造轮子；
  - 报告产出与工单集成。
- **技术栈**：Go + Docker + LLM Agent 编排。
- **关键指标**（2026-11-07 核实）：⭐ 33,583 · 🍴 5,246 · 贡献者 15 · open issue 67 · 最近推送 2026-10-22 · 最新版 v2.2.0（2026-10-05）· **近 7 天提交 0**。
- **适用场景**：授权渗透测试的效率放大器；甲方安全团队的常态化自查；安全教学演练环境。
- **可靠性评估**：**良好，标注观望**。MIT 宽松协议；33.6k★ 体量成熟，issue 消化正常。**但最近一次实质推送是 2026-10-22（16 天前），近 7 天零提交**——相较本期其他项目明显放缓。可能处于大版本间歇期，不排除赛道竞争（strix/shannon 增速更陡）分流了维护精力。使用前建议先看 issue 区是否有关键 bug 积压。
- **上手建议**：仅供**授权测试**使用（内置真实攻击工具）；从 `docker compose` 拉起沙箱环境跑一个靶场（如 DVWA）验证全流程，再考虑接入真实资产；接入前锁定当前版本，关注后续是否恢复活跃发版。

## 4. derv82/wifit3 — 跨平台 USB 无线安全审计工具

> 🔗 https://github.com/derv82/wifit3

- **简介与定位**：经典 Wi-Fi 审计工具 wifite 的**现代化重写**：仅依赖 USB 无线网卡、跨平台（Linux/macOS/Windows），不依赖 aircrack-ng 套件、不打内核驱动补丁。扫描周边网络、捕获 WPA/WPA2 握手包、探测 WPS/WEP 弱点，一条命令完成。对"想学无线安全但被 aircrack-ng 的驱动地狱劝退"的人极其友好。
- **核心功能亮点**：
  - USB 网卡直驱，免内核补丁（wifite 老用户的核心痛点）；
  - 跨平台：macOS 与 Windows 首次可用；
  - WPA/WPA2 握手捕获 + WPS/WEP 弱点利用；
  - 自动化流程：扫描→选择目标→捕获→交给破解工具。
- **技术栈**：Python（wifite 系血脉）+ 用户态 USB 驱动方案。
- **关键指标**（2026-11-07 核实）：⭐ 3,393 · 🍴 363 · 贡献者 18 · open issue 仅 18 · 最近推送 2026-11-07（当日）· 最新版 v0.7.0（2026-11-03）· 近 7 天提交 100+。2026-06 创建，4.5 个月约 750★/月，第三方榜单显示日增曾达 +189★。
- **适用场景**：企业无线网络安全自评（自己的办公 Wi-Fi 有没有弱配置）；安全课程/CTF 无线方向的入门教具；渗透测试的无线侦察环节。
- **可靠性评估**：**良好**。**GPL-2.0**（copyleft，商用集成需注意传染性，已标注）；18 贡献者、open issue 少、当日有推送，18 岁作者单引擎驱动的社区项目但迭代迅猛（v0.7.0 三天前刚发版）；USB 网卡兼容性列表是最大变数，购卡前先查 issue 区确认型号。
- **上手建议**：准备一块推荐型号的 USB 无线网卡（项目 README 有兼容列表）；仅在**自有或获授权**网络上测试；macOS 用户从 v0.7.0 开始体验跨平台能力。

## 5. hevnsnt/CVEngine — 自托管外部攻击面评估平台

> 🔗 https://github.com/hevnsnt/CVEngine

- **简介与定位**：自托管（self-hosted）的**外部攻击面评估平台**（External Attack Surface Management, EASM）：持续发现暴露在公网的资产 → 服务与版本指纹识别 → 匹配在野 CVE → 用**只读安全检查**验证漏洞真实性。差异化卖点是 **AI-first + MCP 集成**：评估结果可以直接喂给开发者的编码 Agent，让"修漏洞"这件事进入 Agent 工作流。
- **核心功能亮点**：
  - 持续资产发现：互联网暴露面自动盘点；
  - CVE 匹配 + 只读 PoC 验证（不打出破坏性 payload）；
  - MCP 接口：漏洞发现可直接进入 AI 编码 Agent 的上下文；
  - 全程自托管，资产数据不出内网。
- **技术栈**：Python。
- **关键指标**（2026-11-07 核实）：⭐ 663 · 🍴 107 · **贡献者仅 4** · open issue 8 · 最近推送 2026-11-07（当日）· 最新版 v1.3.7（2026-11-06）· 近 7 天提交 100+。2026-10-24 创建，仅 2 周即 663★（约 45★/天），是本期增速最陡的新芽。
- **适用场景**：中小企业没有预算买 censys/shodan 企业版的攻击面监控；安全团队每季度人肉资产盘点的自动化替代；给开发 Agent 接一个"我自己哪些服务有洞"的实时数据源。
- **可靠性评估**：**尚可，新芽标注**。**GPL-3.0**（copyleft 已标注）；2 周即发版至 v1.3.7、当日有推送，节奏健康；但**仅 4 名贡献者，bus factor 偏低**，创建时间太短，长期维护承诺未经验证——建议作为试用与观察对象，关键业务暂勿依赖。
- **上手建议**：Docker 自托管，先对自家公网 IP 段跑一轮发现+验证（注意只读模式默认开启）；把 MCP 接口接到内部编码 Agent 试一次"漏洞→工单→修复建议"链路；持续观察其发版节奏再决定是否深度集成。
