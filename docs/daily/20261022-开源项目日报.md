## 1. floci-io/floci — AWS 本地模拟器

**GitHub**：https://github.com/floci-io/floci

### 项目简介与定位
"Light, fluffy, and always free"——AWS 云 API 的本地模拟器，直接对标 LocalStack。2026 年 2 月创建，8 个月冲到 27k Star（约 3,367★/月），是当前 DevOps 赛道增速最快的项目之一。主打完全免费开源（LocalStack 大量核心能力已转向 Pro 付费），覆盖 EC2、S3、Lambda、DynamoDB、SQS、Cognito、CloudFormation、DSQL 等大量服务。

### 核心功能亮点
- 本地运行全套 AWS API，无需真实云账号即可开发与集成测试
- 对 LocalStack 免费版的高保真替代，社区活跃贡献新服务
- 支持 CloudFormation 部署流程（近期已支持 WAFv2 日志配置）
- 迭代极快：从提交记录看，几乎每天都有功能/修复合并

### 技术栈
以云服务模拟为主的多语言实现（含 Go/TypeScript 等），提供 CLI 与容器化运行方式，可无缝接入 pytest / CI 流水线。

### 关键指标（2026-10-22 实测）
- Stars：**27,003**｜Forks：**2,961**｜Open Issues：143
- 贡献者：**约 345 人**，头部贡献者 hectorvent(571 次)、pgermosen(305 次)、okinaka(176 次)——真实人类贡献矩阵，非机器人刷量
- 最近推送：**2026-10-22（今日凌晨仍有 3 次合并）**
- 最新 Release：**v2.3.0（2026-10-15）**
- 许可证：**MIT**（原文核实）

### 适用场景
- 本地/离线开发 AWS 依赖的服务，节省云上测试成本
- CI 流水线中的集成测试（不依赖真实 AWS 凭证）
- 替代 LocalStack 免费版日益缩水的功能面

### 可靠性评估
- **维护活跃度：极高**。创建仅 8 个月，日级提交节奏，release 稳定（2.3.0）
- **社区健康度：优**。345 名贡献者、86 名 watcher，Issue 吞吐量大但修复快
- **许可证风险：无**。MIT 宽松协议
- **风险点**：项目年轻（<1 年），API 兼容性可能随版本快速演进；对 AWS 服务覆盖仍在补齐中，生产关键路径建议做兼容性验证

### 上手建议
```bash
docker run -p 4566:4566 floci-io/floci   # 示例：容器方式启动
# 客户端将 endpoint 指向 http://localhost:4566 即可
aws --endpoint-url http://localhost:4566 s3 ls
```
建议从 S3/DynamoDB/SQS 这类成熟服务开始试点，逐步扩展到冷门服务。

## 2. pranshuparmar/witr — "Why is this running?" 进程溯源工具

**GitHub**：https://github.com/pranshuparmar/witr

### 项目简介与定位
一个回答经典问题"这玩意儿为什么在跑？"的 CLI + TUI 工具：输入任意进程、端口、容器或文件，反向追溯到是**谁、由什么链路、在什么配置下**把它拉起来的。约 2,283★/月 的增速，是今年排障类工具里现象级的新面孔。

### 核心功能亮点
- 对进程、端口、容器、文件四种入口统一溯源
- 输出启动链路（父进程树 → 启动服务/容器编排/定时任务）与关键配置
- CLI 与 TUI 双形态，输出对人和管道都友好
- 跨平台支持 Linux/macOS/BSD，单二进制零依赖

### 技术栈
Go 编写的单二进制 CLI，无需 daemon 常驻。

### 关键指标（2026-10-22 实测）
- Stars：**22,753**｜Forks：**798**｜Open Issues：**仅 2 个**
- 贡献者：**约 45 人**
- 最近推送：**2026-10-19**
- 最新 Release：**v0.3.4（2026-10-04）**
- 许可证：**Apache-2.0**（原文核实）

### 适用场景
- 排查"端口被谁占了""这个进程是谁拉的"——尤其适合容器与 systemd 混杂的环境
- SRE 值班快速定位异常进程的来源
- 替代 `lsof`/`ps`/`systemctl status` 多命令交叉手工排查

### 可靠性评估
- **维护活跃度：高**。3 天内有推送，月度 release 节奏
- **社区健康度：优**。Open Issue 仅 2 个，响应极快
- **许可证风险：无**。Apache-2.0
- **风险点**：功能面较新，v0.x 阶段输出格式可能变动；深度溯源能力依赖系统权限

### 上手建议
```bash
brew install witr        # 或 go install github.com/pranshuparmar/witr@latest
witr --port 5432         # 谁占了 5432？为什么启动？
witr --pid 1234 --tui    # TUI 模式查看完整启动链
```
建议先在个人开发机熟悉输出语义，再纳入团队 runbook。

## 3. Dokploy/dokploy — 开源自托管 PaaS

**GitHub**：https://github.com/Dokploy/dokploy

### 项目简介与定位
"Open Source Alternative to Vercel, Netlify and Heroku"——在一台 VPS 上自建应用部署平台：Web UI 管理 Docker 容器、数据库、反向代理、SSL 证书、多服务器节点。1,262★/月，在自托管赛道仅次于 Coolify 的头部选手，生态成熟度高。

### 核心功能亮点
- Web UI 一站式：应用部署、数据库（Postgres/MySQL/Mongo/Redis）、Cron、备份
- Traefik 自动反代 + Let's Encrypt 自动 SSL，绑定域名即上线
- 多服务器（Swarm）支持，一台管理机托管多个目标节点
- Templates 市场一键部署开源应用；API/CLI 可编程

### 技术栈
TypeScript（Next.js + tRPC）控制面 + Docker/Docker Swarm 执行层，单条 `curl | bash` 即可装到任意 VPS。

### 关键指标（2026-10-22 实测）
- Stars：**37,922**｜Forks：**3,106**｜Open Issues：789
- 贡献者：**约 383 人**
- 最近推送：**2026-10-21**
- 最新 Release：**v0.30.8（2026-09-29）**
- 许可证：**Apache-2.0 + /proprietary 目录专有例外**（LICENSE 原文核实：仓库主体 Apache-2.0，`/proprietary` 目录下的内容按 LICENSE_PROPRIETARY 专有授权）

### 适用场景
- 个人/小团队把 Vercel/Heroku 账单换成一台 VPS
- 内部工具、官网、API 服务的低运维部署平台
- 需要数据出域（自托管合规）的中小团队

### 可靠性评估
- **维护活跃度：高**。日级提交，月度 release；但 789 个 open issue 相对体量偏多，说明需求洪流大于维护带宽
- **社区健康度：良**。383 贡献者、115 watcher、活跃的 Discord 社区
- **许可证风险：低但需知悉**。自用、部署、二次开发（不动 /proprietary 目录）完全自由；对 fork 商业发行需检查专有目录边界
- **风险点**：单机控制面故障即平台故障，建议控制面本身做好备份；v0.x 版本升级偶有 breaking change，生产升级前看 changelog

### 上手建议
```bash
curl -sSL https://dokploy.com/install.sh | sh   # 任意 2C4G 以上 VPS
# 打开 80/443/3000 端口，浏览器完成初始化即可部署第一个应用
```
建议先部署一台非关键应用试运行 2 周，验证备份与升级路径后再迁移生产。

## 4. skyhook-io/radar — 开源 K8s 可视化 UI（内置 MCP Server）

**GitHub**：https://github.com/skyhook-io/radar

### 项目简介与定位
"The missing open-source Kubernetes UI"——单个 Go 二进制提供的 Kubernetes 控制台：故障定位（什么坏了、为什么坏、改了什么）、服务拓扑、事件时间线、Helm/GitOps 视图、实时流量、集群审计，且**内置 MCP Server，可让 AI Agent 直接读取集群状态**。今年 1 月创建，431★/月。

### 核心功能亮点
- 开箱即用的 Web UI，无需在集群部署重型组件
- 问题诊断视图：异常聚合 + 事件时间线 + 变更追踪（谁改了什么）
- 服务拓扑与实时流量可视化
- 内置 MCP server：Claude/其他 Agent 可直接查询集群，适合"AI 运维"工作流
- Helm、GitOps（ArgoCD/Flux）感知

### 技术栈
Go 编写，单二进制分发（也支持容器部署），只读 API 为主。

### 关键指标（2026-10-22 实测）
- Stars：**3,884**｜Forks：**251**｜Open Issues：116
- 贡献者：**约 72 人**（9 个月拉起 72 人，社区动员力强）
- 最近推送：**2026-10-22（今日）**
- 最新 Release：**v1.17.0（2026-10-15）**
- 许可证：**Apache-2.0**（原文核实）

### 适用场景
- 替代 `kubectl get/describe/logs` 交叉人肉排障，给不熟 K8s 的开发者一个"能看懂"的界面
- 值班排查：变更→故障的关联定位
- 让 AI Agent 安全地只读访问集群状态（MCP）

### 可靠性评估
- **维护活跃度：高**。今日有推送，双周级 release（已到 v1.17）
- **社区健康度：良**。72 贡献者，Issue 增长与修复节奏匹配；watcher 偏少（13），社区仍在早期扩散阶段
- **许可证风险：无**。Apache-2.0
- **风险点**：项目仅 9 个月大，UI/数据模型仍在快速迭代；生产集群建议以只读 kubeconfig 接入

### 上手建议
```bash
radar --kubeconfig ~/.kube/config   # 本地起 UI，浏览器访问
# MCP 接入：把 radar 的 MCP endpoint 配入 Claude Code / WorkBuddy 等 Agent
```
建议先用只读 ServiceAccount 接入 staging 集群，重点体验"事件时间线 + 变更追踪"两个诊断视图。

## 5. platform-engineering-labs/formae — 从现状出发的新一代 IaC

**GitHub**：https://github.com/platform-engineering-labs/formae

### 项目简介与定位
"Infrastructure As Code that starts from what already runs"——反向思路的 IaC 工具：先**发现你现有的云资源（drift）**，版本化实际状态，再交还给你可维护的代码。定位为 Terraform/Pulumi 替代品，构建于 Pkl 配置语言之上，同样内置 MCP server。由 Platform Engineering Labs（Pkl 语言同门）出品，今年 10 月刚满一周岁，0.90.x 快速逼近 1.0。

### 核心功能亮点
- 自动发现存量云资源并生成代码（解决 Terraform import 万年痛点）
- drift 持续检测与版本化：手工改动不再是"天书"
- Pkl 语言建模基础设施，IDE 支持好、校验强
- 内置 MCP server，AI Agent 可参与基础设施管理
- 声明式同步模型：代码与云上状态对账

### 技术栈
Go + Pkl（来自 Apple 的配置语言），面向 AWS 起步（Azure/GCP 路线图中）。

### 关键指标（2026-10-22 实测）
- Stars：**775**｜Forks：**43**｜Open Issues：22
- 贡献者：**约 9 人**（核心团队驱动为主）
- 最近推送：**2026-10-08**（两周前）
- 最新 Release：**0.90.5（2026-10-21）**
- 许可证：**FSL-1.1-ALv2（Functional Source License）** ⚠️ —— LICENSE 原文核实。非 OSI 开源协议：禁止竞争性商用，**两年后自动转为 Apache-2.0**（MIT/Apache 式的"延迟开源"模式）

### 适用场景
- 背着大量"手工创建 + 前人遗留"资源的存量 AWS 账号，想开始 IaC 化
- 被 Terraform 的 state 文件和 import 机制折磨过的团队
- 想让 AI Agent 参与基础设施对账与治理的探索团队

### 可靠性评估
- **维护活跃度：中高**。两周前有代码推送，但 release 频率高（0.90.5 在 10-21），说明开发以内部团队节奏快速推进
- **社区健康度：中**。9 名贡献者、22 个 open issue，基本是"官方驱动型"项目，社区生态尚未成形
- **许可证风险：⚠️ 中**。FSL-1.1 非 OSI 开源，禁止将其用于与作者竞争的产品；企业内部使用不受限；2 年窗口后转 Apache-2.0。**若团队政策强制要求 OSI 协议，此项目不合规**
- **风险点**：v1.0 之前的 API 稳定性无承诺；云覆盖以 AWS 为主

### 上手建议
```bash
brew install platform-engineering-labs/tap/formae
formae discover aws    # 扫描存量资源并生成 Pkl 代码
formae apply           # 之后进入声明式管理
```
建议在隔离的测试 AWS 账号先跑 discover，评估生成代码的可读性，再决定是否纳入团队工作流；法务侧确认 FSL 协议与贵司开源政策兼容。
